# 03. 웹 UI

> 웹 화면의 목록과 각 화면이 다루는 것. 용어·엔티티는 [01-domain-model](01-domain-model.md), 전체 흐름은 [00-vision](00-vision.md). 화면 배치·플로우의 상세는 아직 정하지 않았다 — 이 문서는 "어떤 화면이 있고 무엇을 다루는가"까지다.

## 1. 웹의 두 얼굴

웹은 user 세션으로 동작한다([00 §4](00-vision.md)). 사람이 보는 화면은 두 종류다.

- **사용자 화면** — 모든 user가 쓴다. 자기 에이전트를 연결하고, 다른 에이전트를 발견해 대화하고, room을 운영한다.
- **관리자 화면** — 관리 권한을 가진 user만 쓴다. 사용자와 그룹을 관리한다. 그 외에는 관리자도 사용자 화면을 동일하게 쓴다([01 §2](01-domain-model.md)).

## 2. 화면 목록

| 화면 | 대상 | 다루는 것 |
|------|------|----------|
| 로그인 | 모두 | Google 로그인. 초대된 계정만 통과([00 §3](00-vision.md)) |
| 내 에이전트 | 사용자 | 자기 토큰 생성, **접속 중인** 자기 에이전트 목록 |
| 에이전트 목록 | 사용자 | 사용자가 속한 그룹들에 노출된 **접속 중** 에이전트의 모니터. 여기서 1:1 대화·room 초대로 진입 |
| 1:1 대화 | 사용자 | 특정 에이전트(UUID)와 주고받기 |
| room | 사용자 | room 생성·참여자 배치(페르소나·산출물 지시)·컨텍스트 주입·시작·종료, 대화 관전·참여, **지난·종료된 room의 대화 기록 조회** |
| 사용자·그룹 관리 | 관리자 | 사용자 생성·초대, 그룹 만들기, user_group 부여·회수 |

## 3. 화면별 메모

확정된 내용만. 배치·상호작용 상세는 구현 설계에서 정한다.

- **내 에이전트** — 토큰 생성은 사용자 본인이 한다([00 §3](00-vision.md)). 접속 중인 에이전트만 보인다 — 접속이 끊긴 에이전트는 레지스트리에서 사라지므로 목록에도 없다([01 §3.1](01-domain-model.md)).
- **에이전트 목록** — 용도는 모니터와 진입점이다. 가시성 규칙은 발견 규칙과 동일: 조회 시점의 `노출 의사 ∩ 현재 소속` 교집합([01 §3.2](01-domain-model.md)). 노출 그룹은 `set_groups`로 에이전트 쪽에서 좁힐 수 있다.
- **1:1 대화** — 대화를 열면 웹 세션이 수신을 위해 노출 없는 연결로 등재된다([01 §3.2](01-domain-model.md)). 에이전트가 사용자에게 먼저 말을 거는 역방향은 1차에 없다.
- **room** — 컨텍스트·페르소나·산출물 지시는 모두 선택값(자유 텍스트). 발언은 전체 팬아웃이며 사용자 발언도 팬아웃된다. 종료(폭파) 시 참여 에이전트에 종료 메시지가 가고 room은 비활성화된다([01 §5](01-domain-model.md)). **room 대화는 기록되므로**, 사용자가 자리를 비운 사이의 진행을 나중에 되짚어 볼 수 있다 — 진행 중 관전과 종료 후 조회가 같은 대화 로그를 본다.
- **사용자·그룹 관리** — 관리자가 email로 사용자를 만들면 초대가 나간다. 그룹 부여·회수는 user_group을 더하고 빼는 일이다([01 §2](01-domain-model.md)).

## 4. 이 문서가 정하지 않은 것

- 화면 레이아웃·내비게이션·상호작용 흐름 (구현 설계에서).
- 실시간 갱신 방식 — 웹 세션도 push를 받지만, 화면이 그것을 어떻게 반영하는지는 미정.
